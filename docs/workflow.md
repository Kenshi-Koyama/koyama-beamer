# スライドの作り方（進め方）

デザインのルールは [SlideRules.md](SlideRules.md)。ここには「どの順番で決めるか」を書く。
AI アシスタントと一緒に作るときも、このページを最初に読ませる。

---

## 1. 6段階のゲート形式

前の段階に合意してから次の段階に進む。前の段階を飛ばして先の提案（例：大枠が決まる前に
スライドの構成表やレイアウトを出す）をしない。

| 段階 | 決めること | 進め方 |
|---|---|---|
| 1. 大枠 | 誰に向けて、どの角度を押し出し、発表のゴールは何か | 発表者が大枠を出す → メリット・デメリット・リスクを整理して修正・合意 |
| 2. セクション構成 | セクションの並びと、それぞれの役割 | 大枠に沿って流れを整理 |
| 3. セクションの内容 | 各セクションで何を言うか | セクションごとに詰める |
| 4. スライド単位 | 1枚ごとの主張（1枚1メッセージ）と根拠 | 1枚ずつ提案し、発表者が内容を確かめる |
| 5. デザイン・レイアウト | カラーパレット、図・表・2カラムなどの配置 | 最初にパレットを決め（下の 2.）、内容が決まったスライドから配置 |
| 6. 試作 | Quarto でビルドして実物を確認 | PDF を見て、はみ出し・文字の大きさを直す |

- 内容を相談する段階（1〜3）では、構成表や枚数をこちらから先に出さない。まず大枠についての考えを聞く。
- 研究計画の発表では「ストーリー」= 文献の整理 → リサーチギャップ → それに基づく RQ → 文献への貢献・新規性・位置づけ、
  の一続きの筋。論点を個別に掘り下げるより、この筋を組み上げることを目標にする。

## 2. カラーパレットを決める（段階5の最初）

テンプレートの既定のパレット（[SlideRules.md](SlideRules.md) の 1.）を使うか、この研究用に変えるかを毎回決める。
図を作り始める前に決める（図の色をスライドと同じにするため）。

確かめること：

- 論文やこれまでの発表の図で、すでに決まっている色はあるか（例：重症度ごとの色、処置群・対照群の色）
- 研究の中に「2つの群の対比」があるか。あるなら、どちらを accent・どちらを primary にするか
- 発表の場（ゼミ・学会・投影環境）で読みにくくならないか（色覚の多様性、白背景とのコントラスト）

決まったら：

- 変えるなら YAML の `palette:` に書く（[recipes.md](recipes.md) の 7.）。役割の分け方（構造・強調・データの注目点）は変えない
- 図を作るコードにも同じ16進の色を書く（スライドと図で色をそろえる）
- 決めたことは研究のノートに残す（次の発表でも同じパレットを使えるように）

## 3. 文言を書くとき（段階4〜5）

- 内容の合意（何を言うか）と文言化（どう書くか）は別の作業。合意した内容を、スライド用に**体言止め・断片・矢印（→）**に切る。
  完全な文章（〜である、〜する）を並べない。
- 1枚に言いたいことは1つ。それを支えるのは最小限（1〜3項目）。細かい数字や補足は発表原稿・付録へ。
- 発表原稿も同じ：1枚あたり言いたいこと1つ＋1〜3文から始め、足りなければ足す。

---

## 4. 図・表を作るとき

- 作る前に「どの変数を、どの形（標本・単位・指標・区分）で描くか」の一覧を作って合意してから実装する。
- 図はスライドの実寸で作る（幅 4.25 インチ・300dpi など。[SlideRules.md](SlideRules.md) の 7.）。
- 分析コードから図表を書き出し、手で編集しない（数値が変わっても作り直せるように）。

---

## 5. 頼むときに伝えると早いこと

- 発表の**目的・想定聴衆・持ち時間**（枚数感と、Outline を入れるか＝`section-outline` が決まる）
- **タイトル / 発表者 / 日付 / 学会・ゼミ名**
- **中身**：論文やドラフト（要約して構成する）
- **図**：ファイルパス（どのスライドにどの図か）
- **引用**：`.bib` のキー、または文献情報
- **特殊なスライド**：特定の表・数式・図解（決定木など）
