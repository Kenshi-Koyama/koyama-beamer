# 発表スライド作成ルール（Quarto → Beamer）

> このテンプレート（`koyama-beamer`）でスライドを作るときのデザインのルール。
> 出力は **Quarto → Beamer PDF**（lualatex / metropolis + miniframes / Noto Sans + Noto Sans JP、4:3）。
> 各ルールの実装（色・部品の定義）は `_extensions/koyama/beamer-preamble.tex`、使い方の実例は `template.qmd`。

---

## 0. 基本方針（1行で）

**「1枚 = 1メッセージ」**。リード文・箇条書き・`⇒` の結論は、そのスライドに必要なときだけ使う
（図や表だけのスライドがあってもよい）。
色は「構造」と「強調」を厳密に役割分担し、余白を惜しまない。図は主役なので、なるべく大きく見せる。

---

## 1. カラーパレット（この設計の核心）

色は**役割の名前**で呼ぶ（`primary` = 構造、`accent` = 強調、`highlight` = データの注目点）。
下の表の「既定の色」は**既定のパレット**で、研究によって変えてよい（例：論文の図ですでに使っている色にそろえる）。
変えるかどうかは、スライドのデザインを決める段階で毎回考える（[workflow.md](workflow.md) の 2.）。
変えるときは YAML の `palette:` で色を差し替える（[recipes.md](recipes.md) の 7.）。
色を差し替えても、名前と役割はそのままなので、このページのルールはそのまま使える。

| 色名 | 既定の色（RGB） | 役割（この1点に限定して使う） |
|---|---|---|
| `textmain` | 黒に近い灰（42,46,51） | 基本テキスト・`Table X:`/`Figure X:` のラベル |
| `textmuted` | 灰（141,142,143） | 出典 `(Author, Year)`・`Note:`・非アクティブなナビ |
| `background` | 白（255,255,255） | 背景（原則ベタ塗りしない） |
| **`primary`** | 青（54,136,214） | **構造の主役**：箇条書きの●／ブロックタイトル／セクションナビ／付録ボタン。**文中キーワード強調**にも使ってよい |
| `primarymid` | `primary` の 35%（自動） | ブロック本文の地色／ナビバーの地色 |
| `primarylight` | 淡い青（227,241,255） | frametitle帯の地色／**数式の変数定義ボックスの地色** |
| **`accent`** | 赤（210,48,55） | **文中キーワード強調**／対比の一方（例：処置群 vs 対照群の片側）。白背景コントラスト比 約5.0:1（WCAG AA本文基準クリア） |
| `accentlight` | 淡い赤（249,183,185） | alertブロック本文の地色 |
| **`highlight`** | 橙（240,199,74） | 表・数値の「枠／セル背景」ハイライト（"ここを見て"）専用。**文字色には絶対に使わない**（白背景コントラスト比 約1.6:1しかなく、プロジェクター投影では特に読めない） |

### 色の3原則
1. **`primary`＝構造＋文中キーワード強調、`accent`＝文中キーワード強調・対比の一方、`highlight`＝データの注目点**。
   `primary` は箇条書き点・帯などの「構造」用途に加え、**対比相手が無い単独の文中強調**にも使ってよい
   （例：その回の主役概念1つだけを強調）。ただし多用すると構造色との区別が曖昧になるので、
   1枚のうち「構造としての `primary`」と「強調としての `primary`」を同時に多用しすぎない。
2. **1枚あたりの強調は絞る**：文中の `accent`/`primary` 強調は合計で原則2〜3語まで、`highlight` は表の中の1〜2箇所まで。
3. **対比（2グループ）** は `primary ↔ accent` の文字色で表す（例：`\textcolor{primary}{対照群}` vs `\textcolor{accent}{処置群}`）。
   二色の枠で対比させることはせず、代わりに**表内の注目セルは `highlight` の枠/背景**で示す。
   図でも同じ割り当て（例：処置 = `accent`、対照 = `primary`）にそろえる。

### 実装メモ
- 文中強調：`\textcolor{accent}{...}` / `\textcolor{primary}{...}` を直接使う（太字併用は`\textcolor{accent}{\textbf{...}}`）。
  `\alert{...}`はbeamerの`alerted text`色（=`accent`）しか使えず `primary` に対応できないため、
  共通の書き方として`\textcolor`に統一する（**`\alert` は使わない**）。
- 表のセル背景：`\cellcolor{highlight!25}セル内容`（`colortbl` はプリアンブルで読み込み済み）。
- 表の値やまとまった文章を「枠」で囲む：表の中の値は `\ybox{...}`、複数行の文章は `keytakeaway` 環境。
  **文中の一部分だけを枠で囲まない**（例：「閉館時刻を［20 時以降］に延長」のように文の途中を囲うのは不可）。
  文中の語句を目立たせたいときは `\textcolor{accent}{...}` などの文字色で強調する。

## 2. レイアウトと情報量

- **1枚1メッセージ**。詰め込まない。行間・段落間の余白（`\vspace`）を積極的に取る。
- **よく使う型**（必須ではない。スライドの役割に合わせて部品を選ぶ）：
  1. 上部に**リード文1〜2行**（そのスライドの主張）。タイトルで主張が言えていれば要らない。
  2. その根拠・詳細を箇条書き（最大3階層）。
  3. 最下部に `⇒` または `→` で**結論/含意を1行**。
     そのスライドで一番覚えてほしい核心の一文（議論の転換点・研究の新規性など）は、
     矢印の代わりに `keytakeaway` 環境（`highlight` の枠）で視覚的に格上げしてよい。
     ただし多用すると効果が薄れるので、1デッキで数回程度・本当に格上げしたい一文だけに絞る。
- 数式は**原則1枚1本**（IVのように第1・第2段階を並べるときは例外的に2本まで）。
- frametitleは `primarylight` の帯。表紙と目次にはタイトル帯を付けない。
- **スライドのタイトルは黒字だけ**。タイトルに `accent`/`primary` などの色・強調を使わない
  （発表者の見解を述べるスライドでも同じ。見解であることは本文の言葉で示す）。

## 3. 箇条書き（階層ルール）

| 階層 | 記号／色 | 用途 |
|---|---|---|
| L1 | `primary` の ● | 主要な論点 |
| L2 | `primary` の ●（小） | L1の具体・補足 |
| L3 | 小さい ● または数字 `1. 2.`（`primary`） | さらに細分・列挙 |

- **論理展開は `→`、結論・帰結は `⇒`**（矢印で流れを見せる）。
  **矢印で始める項目には ● を付けない**（「● →」と記号を2つ並べない）。
  Markdown では `- $\to$ …` や `- → …` と書けば、テンプレートが自動で ● の位置に矢印を置く。
- 見出し語だけ太字にしてメリハリ（例：**Research Question**、**Data**、**Method**）。
  **太字の見出し語には ● を付けず、左端から書く**。子の項目は見出しの下に、1段目の箇条書きとして並べる。
  Markdown では普通に `- **Data**` と書き、その下に子の箇条書きを置けば、テンプレートが自動でこの形にする
  （太字だけの項目で、子の箇条書きがあるときだけ。子がない太字の項目や、太字のあとに通常の文字が続く項目は
  普通の箇条書きのまま ● が付く）。この形は縦に長くなるので、収まらないときは項目を減らすかスライドを割る。
- 数式内の変数はイタリック（`$X$`, `$Y_{jt}$`）。本文はサンセリフ（Noto Sans）で統一。
- 1つのL1配下は**2〜4項目**が目安。5項目を超えるならスライドを割る。
- **「Findings / Policy Implications」型のまとめスライド**を標準とする：
  「Findings」「Policy Implications」を別々の太字の見出しにし、それぞれの下に詳細を2〜3項目展開する
  （知見・含意がそれぞれ複数あることを前提にした型）。

## 4. 左右2カラム（`columns`）

- **左＝視覚物（図・表・数式・決定木）、右＝解釈の言葉**、を基本形にする。
- 右カラムは「読み解きの箇条書き」に徹する（結論・βの大小・メカニズム）。装飾しない。
- **幅は決め打ちしない**。スライドごとに、図をなるべく大きく見せつつ、右の文字が細切れに折り返さない幅を探す。
  - 4:3 では本文の幅が約 108mm しかない。右カラムを 40% 前後にすると、日本語は1行に約12字で折り返す。
    右の文を短く切る（体言止め・矢印）か、図を大きくしたいなら2カラムをやめて中央1枚にすることも考える。
- 図が主役のスライドは左右分割せず**中央1枚**で大きく見せてよい（分布マップ・イベントスタディ等）。

## 5. 数式と変数定義ボックス

- **数式を上部**に置き、右端に式番号 `(1) (2) (3)`。
- その**変数定義だけ**を `primarylight` 地の**ボックス（`defbox` 環境）で囲む**＝「定義ゾーン」を視覚的に隔離。
  - ボックス内は太字の見出し `Outcome variable` / `Main explanatory variables`（● なし）＋各変数の定義。
  - 定義文中のキーワードは `\textcolor{accent}{...}` で強調。
  - 参照カテゴリなど重要な注記は `accent` の1行で（例：「基準は導入の前年」）。
- 囲み（ボックス）は次の3種類だけ。普通の箇条書きを囲まない。
  - `defbox`（`primarylight` 地）：数式の変数定義
  - `bluebox`（`primary` の細い枠だけ）：定義・補足情報を本文と軽く区切りたいとき。
    使うかはスライドごとに判断する（ふだんは使わない。補足は箇条書きや `Note:` で足りることが多い）
  - `keytakeaway`（`highlight` の枠）：核心の一文（2. を参照）

## 6. 表（Table）

- **縦罫線なし・横罫線のみ**（`booktabs`：`\toprule` `\midrule` `\bottomrule`）。
- ラベル `Table X:` は**黒の太字**（`\tlabel{Table 1:}`）、続く説明は黒の通常。表の**上**に置く。
- **注目セルは `highlight`** の背景（`\cellcolor{highlight!25}`）またはセルの値を枠（`\ybox{...}`）で囲んで強調。片側だけを目立たせる。
- **対比が必要な列/セル**は、注目したい方を `highlight`、対になる文字は `primary`/`accent` で色分け（二色の枠の対比は使わない）。
- 表の下に、
  - `Note:` … 補足（`\slidenote{...}`：`textmuted`・小さめ）
  - `*** p<0.01, ** p<0.05, * p<0.1` / 標準誤差の説明（詰めて書きたいときは `\tinynote{...}`）
- 幅が広い回帰表は**左右分割せず全幅**で置き、解釈は別スライド or 表の右に短く。
- **書き方の使い分け**：セル背景強調（`\cellcolor`）や特殊な装飾が必要な表は生LaTeX（`tabular`/`tabularx`+`booktabs`）で書く。
  強調不要な単なる説明用の表（データ一覧・変数一覧など）は、Markdownのパイプテーブルで手早く書いてよい
  （PandocのLaTeX出力も`booktabs`スタイルになるので「縦罫線なし」の見た目は崩れない。
  セル内に`\textcolor{accent}{\textbf{...}}`等の生LaTeXを埋め込むことも可能）。
- 分析コードから表を出すときは、`tabular` だけの LaTeX 断片（booktabs）を書き出し、スライド側で
  `\begin{center}\small\input{…/table.tex}\end{center}` のように貼る。はみ出すときは `\footnotesize` と
  `\renewcommand{\arraystretch}{0.9}` で詰める。

## 7. 図（Figure）

### 方針：図はなるべく大きく見せる

図を見せるスライドでは図が主役。型を決め打ちせず、**スライドごとに、その図を一番大きく見せる配置を慎重に考える**。
使える手段（効果の大きい順。4:3・既定の余白での実測）：

| 手段 | 効果 |
|---|---|
| リード文をやめ、主張をスライドのタイトルに書く | 図の高さが約 2.15 → 約 2.4 インチに |
| 2カラムをやめて中央1枚にする | 図の幅が約半分 → 本文の幅いっぱい（4.25 インチ）に |
| 図の縦横比を、空いている高さに合わせて作り直す | 空きを使い切れる |
| キャプションと注を1行にまとめる・注を減らす（細かい注は口頭か付録へ） | 数 mm〜1行分 |
| `center` 環境をやめて `{\centering ... \par}` にする（上下の余白が減る） | 数 mm |

- どれを使うかは、そのスライドで何を伝えたいかで決める（リード文が要る図、2カラムで解釈を並べたい図もある）。
- 縦横比（4:3）と左右の余白（1cm）はテンプレート全体の設定なので、スライドごとには変えない。

### 図の作り方（実寸で作る）

拡大縮小すると文字の大きさが狂うので、図はスライドに貼る実寸で作る。

- 4:3 の本文の幅 ≈ **4.25 インチ**（用紙 128mm − 左右の余白）。図は幅 4.25 インチ・300dpi の PNG で作り、
  `\includegraphics[width=\linewidth]{…}` で等倍に貼る。
- 高さの目安（中央1枚・幅 4.25 インチ）：
  - タイトル＋リード1行＋図＋キャプション＋注2行 → **約 2.15 インチ**まで
  - タイトル＋図＋キャプションと注（2行まで）→ **約 2.4 インチ**まで（2.6 インチではキャプションがはみ出した）
- 文字：フォントはスライドと同じ Noto Sans JP、軸 8.5pt・凡例 9pt。
- 図の中にタイトル・注は入れない（スライドのタイトル・リード文と `Note:` 行に書く）。N は凡例かパネルの見出しに。
- 群は色だけに頼らず形も変える（例：処置 = `accent` ●、対照 = `primary` ▲）。
- 新しい図は、テスト用のデッキで実寸に貼って、はみ出し・文字の大きさを目で確認してから本番に使う。

### その他

- ラベル `Figure X:` は**黒の太字**（`\tlabel{Figure 1:}`）、図の**下**に置く。続けて `(source: ...)` を `textmuted` 小さめで。
- 図は `keepaspectratio` で歪ませない。1枚に図は原則1〜2点。
- 決定木・DAG は tikz（`box_node`=`primary` 系／`key_node`=`accent` 系、`dag_node`/`arrow` スタイル）。
  - 通常ノードは `primary` 系、**結論となる1ノードだけ**を `accent` 系で差別化。
- 図がまだ無いときは `\figplaceholder[幅]{ファイル名}` で仮置きする。

## 8. 引用・出典

- 本文引用は `(Author, Year)`、`textmuted` の小さめ。強調しない。
- 参考文献は APA（`biblatex` + biber）。末尾に `allowframebreaks` の References スライド。
  - 文献リストの文字は小さくして（7pt・行送り 8.4pt）、1枚になるべく多く載せる（2行の文献で1枚に約8本）。
    リストは発表中に読ませるものではないため。
  - さらに小さく・大きくしたいときは、そのデッキの `deck-preamble.tex` で
    `\newcommand{\koyamaBibSize}{\fontsize{6}{7.2}\selectfont}` のように指定する。
  - 本文中：`\textcite{key}` →「Author (Year)」、`\parencite{key}` →「(Author, Year)」。
  - `.bib` の題名の固有名詞は `{}` で囲む（APA は題名を小文字化するため。例：`{New Jersey}`）。
- 図表の出典は図表ラベル付近に簡潔に。
- **箇条書きの各項目が個別の文献に基づく場合**（例：複数の実証結果を1項目1本ずつ列挙する導入スライド）は、
  項目本文の直後に `\srcite{key}` を添えて、主張と出典を1対1で対応させる
  （`\srcite` = `\slidenote{\mbox{\parencite{key}}}`。(Author, Year) が途中で折り返さない。
  `textmuted`/白のコントラスト比 約3.3:1とWCAG AA本文基準は下回るが、
  出典はリアルタイムで読ませる情報ではなく意図的な弱調子なので許容する）。

## 9. ナビゲーション・全体構成

- 上部に**セクション進行バー**（metropolis + `miniframes`）を常時表示。現在セクションは黒字、他はグレー、丸印で位置を示す。
- 右下にページ番号のみ。付録（`\appendix`）はページ番号から除外（`appendixnumberbeamer`）。
- 各セクションの冒頭に Outline（目次）を自動で入れる。現セクションを `primary`、他を淡色。
  - **短い発表（15〜20分）では YAML に `section-outline: false`** を書いて Outline を入れない。
    現在位置は上部のナビバーだけで示す。
- 付録へのジャンプは `primary` の**ボタン**（`\hyperlink{ラベル}{\beamerbutton{…}}`、飛び先に `\hypertarget{ラベル}{}`）。

## 10. やってはいけない（醜さ回避チェックリスト）

- [ ] 色を増やしすぎない（1枚で `primary`＋`accent`＋（必要時）`highlight` まで。新色を足さない）。
- [ ] ボックスを多用/入れ子にしない（囲みは `defbox`・`bluebox`・`keytakeaway` の3種類だけ。5. を参照）。
- [ ] `highlight` をテキスト色に使わない（背景/枠のみ。白背景コントラスト比が低く読みにくいため）。
- [ ] スライドのタイトルに色・強調を使っている → 黒字だけにする。
- [ ] 文中の一部分を枠（`\ybox`）で囲っている → 文字色の強調にするか、表の中に移す。
- [ ] 「● →」と記号が2つ並んでいる → 矢印の項目には ● を付けない。
- [ ] 文中 `accent`/`primary` 強調が合計1枚に4語以上 → 強調が効かないので削る。
- [ ] 1枚に数式2本以上（IV例外を除く）→ スライドを割る。
- [ ] 箇条書きが4階層 → 3階層までに再構成。
- [ ] 図の歪み・出典漏れ・`Table/Figure` ラベル漏れ。
- [ ] 図が小さい（7. の手段で大きくできないか）。
- [ ] 何を言いたいスライドかがわからない（タイトル・リード文・図表のどこかで主張が伝わるか）。
- [ ] 余白ゼロの詰め込み → 情報を次スライドへ分割。
- [ ] `\alert` を使っている → `\textcolor{accent}{...}` に置き換える。

## 11. 設計意図 → 実装 早見表

| 見た目 | 実装 |
|---|---|
| 上部ナビバー | `\useoutertheme[subsection=false]{miniframes}` |
| frametitle帯 | `\setbeamercolor{frametitle}{fg=textmain,bg=primarylight}` |
| ●箇条書き | `itemize`（記号色を `primary` に） |
| 文中強調 | `\textcolor{accent}{...}` / `\textcolor{primary}{...}`（太字併用は`\textcolor{accent}{\textbf{...}}`） |
| 変数定義ボックス | `defbox` 環境 |
| 補足の囲み（ときどき） | `bluebox` 環境 |
| 表の注目セル | `\cellcolor{highlight!25}...` |
| 表の中の値の注目枠 | `\ybox{...}`（文中には使わない） |
| 矢印の項目（● なし） | `- $\to$ …` / `- → …`（自動） |
| 複数行の要点強調 | `keytakeaway` 環境 |
